## What this establishes

- The agent recognizes every tested missing required field and does not create partial database rows while required user facts are absent.
- It recognizes optional fields in the provider, purchase, and roast schemas and usually omits them instead of interrogating the operator.
- Successful flows create a server-held pending operation and execute that exact operation only after a separate confirmation.
- A prose proposal is not reliably equivalent to a stored pending operation. This distinction must be enforced by the harness rather than left to the model.
- Multi-turn entity resolution is the weakest path. Two references in one purchase can result in only the first lookup being completed, followed by stale or invalid identifiers on the next turn.
- Tool-name fidelity is nondeterministic. Invalid compact names are rejected safely, but recovery adds a call and model hop.
- In an earlier focused run, the uncertain voice-note case also invented an unsupported optional `notes` value. The authoritative full run did not repeat that exact error, but it failed differently. This variance supports enforcing field provenance at the boundary.
