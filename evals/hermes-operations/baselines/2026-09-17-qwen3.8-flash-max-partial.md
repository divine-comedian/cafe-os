# Qwen3.8 Flash max — partial-request benchmark

Code under test: `afeb48a` plus the evaluation-only max-budget changes committed with this scorecard  
Main model: `qwen/qwen3.8-flash` via OpenRouter  
Reasoning: `max`  
Intent router: `deepseek/deepseek-v4.1-flash`, reasoning disabled  
Suite: seven partial-request scenarios, 19 turns

## Budget configuration

The max run was given materially more headroom than previous tiers:

- OpenRouter wire output ceiling: 32,768 tokens per request
- Cafe middleware ceiling: 16,384 completion tokens per model hop
- Aggregate completion budget: 65,536 tokens per user turn
- Reserved tool-free wrap-up capacity: 2,048 tokens
- Hermes evaluation wall-clock budget: 180 seconds per turn
- Runner process timeout: 240 seconds per turn
- Operational workflow hop limits: unchanged

The live trace reported 65,536 completion tokens available at the start of each turn. Failed multi-hop turns retained more than 62,000 tokens at termination, and no turn approached the aggregate completion ceiling. One failing scenario used 10,302 output tokens across its two turns, demonstrating that the former 8,192-token turn budget was no longer constraining the run.

## Findings

Max preserved canonical tool-name fidelity, but it regressed from high on purchase workflows:

- the missing-weight purchase resolved names but stopped without creating the pending proposal;
- the required-only purchase consumed additional reads and reasoning without completing the proposal/confirmation sequence; and
- the uncertain voice-note flow again performed unnecessary reads, reached workflow hop limits, and converted the user's confirmation into a new pending proposal rather than executing an existing one.

Provider, green-lot, roast, and update scenarios passed. No incomplete initial request caused a REST mutation.

The regression is not an output-limit artifact. Max had unused token and time capacity when it failed. Additional reasoning encouraged longer deliberation and more reads but did not improve the model's adherence to the external proposal state machine.

## Decision

Use `high`, not `max`, for the next Qwen3.8 Flash iteration. Max reduced correctness from 6/7 to 4/7, used 52.5% more combined tokens, cost 32.9% more, and took 104.4% more summed wall time than high.

Keep the expanded limits as an evaluation-only capability so future max-tier tests are not accidentally truncated. Normal and production runs retain their existing limits unless explicitly configured otherwise.

Raw reports remain in the ignored `../results/` directory and are not committed because they contain transient session identifiers and verbose traces.
