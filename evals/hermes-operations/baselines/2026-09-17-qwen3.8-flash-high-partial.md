# Qwen3.8 Flash high — partial-request benchmark

Code under test: `1dfe39d`  
Main model: `qwen/qwen3.8-flash` via OpenRouter  
Reasoning: `high`  
Intent router: `deepseek/deepseek-v4.1-flash`, reasoning disabled  
Suite: seven partial-request scenarios, 19 turns

OpenRouter documents Qwen3.8 Flash as supporting native tool calls and configurable reasoning. Model reference: <https://openrouter.ai/qwen/qwen3.8-flash>

High reasoning is a material improvement on this sample. It doubled the scenario pass count while reducing hops, tokens, measured cost, and summed wall time. Unlike the medium baseline, the high run emitted no nonexistent compact tool names.

## Passing behavior

Qwen high passed all six non-voice scenarios, including:

- required-field clarification followed by exact proposal and confirmation;
- two-reference purchase resolution after a missing-weight follow-up;
- a purchase containing only required fields while omitting every unknown optional;
- provider and roast drafts with minimal valid fields; and
- target clarification followed by an exact patch and confirmation.

This includes the required-only purchase that GLM 5.3 high failed twice.

## Remaining failure

The complete run failed the uncertain voice-note scenario. On its second turn, the intent router selected a provider lookup even though provider and lot still required human clarification. Qwen queried the ambiguous name `Sierra`, then later refused to resolve the supplied lot name itself and requested its UUID from the operator. No mutation occurred.

The isolated retry handled the first two clarification turns correctly and resolved both references. It still failed to call `create_purchase` before the hop cap. On the user's following confirmation, it created a new pending proposal rather than executing a stored one and invented an optional `notes` value not supplied by the operator. No REST mutation occurred, but the proposed payload violated field-grounding policy.

The repeated scenario therefore remains nondeterministic and not release-ready. Higher reasoning fixes the sampled tool-name corruption but does not guarantee proposal-state or optional-field provenance across the longest clarification flow.

## Decision

Do not test `qwen/qwen3.8-27b` yet under the stated decision rule: Flash high improved from 3/7 to 6/7 and is both cheaper and faster than the medium baseline in this run. Keep the production default unchanged until the user explicitly approves the reasoning change.

The next engineering step should enforce clarification state and proposal provenance at the harness boundary, then repeat Flash high at least three times. If it cannot pass consistently after that fix, test Qwen3.8 27B using OpenRouter's latency-first provider routing.

Raw reports remain in the ignored `../results/` directory and are not committed because they contain transient session identifiers and verbose traces.
